# Feature Specification: 入库自动获取成本

**Created**: 2026-10-17  
**Status**: Ready  
**Input**: 以后录入卡片自动发起成本录入，能获取则录入，手机和网页版一致。

## User Scenarios & Testing

### User Story 1 - 两端入库后自动获取（P1）
用户在手机确认入库、网页手动录卡或扫描自动入库后，无需另点成本查询；后台查找其已连接卡淘账号的购买订单。
独立验收：新卡入库即产生一项持久任务，关闭客户端仍可运行；唯一可靠订单写入卡价与运费。

### User Story 2 - 不确定或不可用时保留原值（P1）
已有交易不覆盖；多笔候选、搜索不完整、无结果、账号未连接或需验证均不填写成本，保留人工处理入口。
独立验收：每类结果有可查询状态，记录保持不变，其他账户不能读取。

### Edge Cases
入库事务回滚不留任务；重复执行不重复写交易；批量录卡各卡独立；并发人工录入优先保留；网络暂时失败有限重试；服务重启后继续未完成工作。

## Requirements
- FR-001：所有共用入库入口在成功创建无采购交易的新卡时自动排队，已有采购信息不排队。
- FR-002：任务仅操作创建者所有的新卡，不扫描历史全库，不阻塞入库请求。
- FR-003：复用现有订单核验与分摊运费规则；仅唯一通过自动核验的订单写入；保留来源证据。
- FR-004：未知成本保持未知，不用市场估值替代成本；人工成本及任何已有交易均不覆盖。
- FR-005：持久任务支持去重、重启恢复、有限重试及按用户隔离的状态读取。
- FR-006：账号未连接或需验证时停止自动尝试，保留现有手工重试入口，不自动发送短信。

## Key Entities
新入库卡片；所属账户；自动成本任务；已有购买订单与成本证据。

## Assumptions
以创建收藏记录为触发时机，手机仍需完成现有身份确认；补拍已有卡片不新建任务。复用已保存的卡淘账号，不增加手机账号管理页。此次不追溯历史卡库，也不包含生产部署。

## Success Criteria
- SC-001：手机/网页共用入口创建的无成本新卡各产生且只产生一个任务。
- SC-002：唯一可靠订单可自动写入，重复执行无重复交易。
- SC-003：已有交易、多候选、无结果及账号不可用样本均不错误写成本。
- SC-004：隔离数据库验证任务与卡片事务一致、跨账户不可读和失败重试上限。

## 2026-10-28 修复：账号验证不能静默阻塞

实际云端批次887–911的25个自动任务均执行一次后返回account_required / VERIFICATION_REQUIRED，前端只在手动获取成本时显示账号表单，用户没有收到提醒。

- FR-007：登录后的网页与手机主动读取当前账户未删除、无交易卡片的自动成本账号阻塞汇总；进入页面、恢复前台和轮询均能发现，不能依赖打开单卡成本面板。
- FR-008：有阻塞时主动弹出登录/短信验证窗口，说明受影响张数；关闭后保留可重新打开的提醒，同一批同一账号状态不重复自动弹出，新阻塞批次可再次提示。退出/切换账号时取消请求并清空提醒，旧响应不得污染新用户。
- FR-009：复用现有账号表单与官方滑块；读取提示不得发起登录或发送短信。账号成功连接后只将本用户因账号阻塞停止的自动任务重新排队，已有交易、删除卡、其他失败、其他用户均保持原状；正常任务与原成本核验规则保持。
- SC-005：真实组件测试复现后台account_required弹窗、关闭去重与重新打开、延迟失败和账户切换；隔离PG验证汇总隔离及真实登录后的受限恢复。
