# 实施计划

技术栈：Next.js 15 / React 19 / TypeScript，FastAPI / Python 3.12 / psycopg / PostgreSQL。沿用架构；不增加依赖、持久表或生产缓存。

## 宪章检查

保留已有修改、账户条件和图片授权；不改识别或估值算法；先失败测试再实现，报告验证限制。

## 顺序与验证

1. 后端：portfolio_search.py 下推等价过滤，保留 Python 匹配排名；repository.py 流水限定已读取卡片。测试 SQL 参数和空集合，运行搜索/投影及隔离 PostgreSQL 回归。
2. 列表：lib/api.ts 独立列表/汇总请求；app/page.tsx 汇总和计数独立受版本保护。搜索/排序/页大小/分页重用汇总，写入和轮询刷新。测试挂起、失败、旧响应。
3. 详情：app/page.tsx 核心优先，辅助并行、请求版本保护；新增辅助加载、错误及重试，关闭和会话失效使旧请求无效。DOM 测试挂起、失败、切卡、关闭。
4. 图片：image_service.py asyncio.to_thread 保持原校正参数和异常；item-image-upload.ts 等待全部上传 settled 再返回/抛错，接入录入。线程及并发失败测试。
5. 验证：目标单测、真实 PostgreSQL、Web 类型检查与 DOM 回归；记录受控延迟和工作量，审查本轮差异。

## 决策

独立汇总而非新缓存；SQL 仅下推等价非文本过滤；不以 SQL 原始估值代替联合估值排序。图片校正移出事件循环后并发上传，所有上传结束后才消费队列。

## 审查重点

旧会话响应、空 ID、未知数值、参数顺序、辅助失败、部分图片失败、双面更新锁、估值轮询、写入汇总和队列消费。

补充索引任务：保留现有基础索引，为稳定分页、首笔买入、兼容估值、撤销身份和最新复核任务添加五个热点索引；对前三条查询以自然优化器计划验证，不禁用顺序扫描。只在隔离数据库应用迁移。
