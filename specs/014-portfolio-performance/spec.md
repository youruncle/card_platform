# 卡库交互性能优化

日期：2026-10-11。用户已授权实施搜索、详情、录入优化及相关新发现。

## 用户场景与验收

### US1 搜索与浏览（P1）
列表独立于汇总和纠错计数显示；搜索、切页和排序不重复计算账户汇总。结构化筛选提前缩小数据库结果集，中文别名、宽松关键词排名、空值及最终估值排序保持现有语义。
验收：挂起/失败的汇总或计数不阻止卡片显示；筛选改变不重算汇总；写操作及估值轮询更新汇总；旧账户/旧请求不覆盖当前结果；SQL 筛选与原 Python 匹配一致。

### US2 详情渐进加载（P1）
核心详情就绪即显示，纠错、复核和图鉴独立加载。辅助请求失败可见且可重试；切换卡片、关闭或切换账户后旧响应不得更新当前详情。
验收：挂起辅助接口仍可查看核心详情；旧响应被丢弃；辅助加载中不可误认为没有纠错；核心详情只计算目标卡。

### US3 录入和并发响应（P2）
正反面同时上传，所有上传结束后才能清理队列和完成录入。CPU 图片校正不阻塞异步服务其他请求；保持图片校正逻辑、数据库更新、鉴权不变。
验收：两个上传同时启动；任一失败时等待另一上传结束；未上传成功不消费扫描队列；校正在工作线程执行，异常正常传播。

## 功能要求

- FR001 保留用户未提交修改，只改当前范围；不修改真实卡库或部署。
- FR002 不引入跨账户数据缓存，写操作及轮询刷新汇总。
- FR003 流水查询限定到实际展示卡片，空结果不扫描账户流水。
- FR004 等价数字、布尔、持有状态条件参数化下推；文本别名沿用现有匹配规则。
- FR005 记录实测范围，不宣称未测量的线上提速比例。

## 成功标准与边界

搜索不再因更新汇总计算非候选卡；列表不等待汇总/计数，详情不等待复核；分页流水限定本页；双面上传重叠；相关单测、隔离 PostgreSQL 和类型检查通过。
保持排序快照语义；估值/利润排序仍计算候选集合。搜索沿用当前汇总，手动刷新、写操作、估值轮询读取新汇总。长期搜索索引/全库投影缓存需另行设计。
