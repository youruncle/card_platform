## 本轮实现

- 详情只投影目标卡，流水只读取实际返回的卡 ID；空结果跳过流水查询。
- 等价结构化筛选条件下推到 PostgreSQL，中文别名和宽松关键词排名继续使用原 Python 规则。
- 列表独立于纠错计数及筛选时的汇总显示。搜索、排序、页大小、分页重用汇总；写操作、手动刷新、估值轮询读取新汇总。
- 无筛选且需要新汇总时，从同一次全库投影生成列表与汇总，避免重复计算。
- 估值轮询创建新快照，不再重复读取冻结快照。
- 核心详情优先显示，复核、纠错、图鉴独立加载。辅助错误可重试，切卡、关闭、重试和会话结束丢弃旧响应。
- 正反面图片同时上传，所有上传结束后才返回成功或错误，失败不消费扫描队列。
- 图片校正移到工作线程，算法、输入参数、输出及异常处理不变。
- 独立审查发现的登录过期后旧账户数据保留问题已修复，并有 RED→GREEN 回归。

## 真实数据库对照

在隔离库创建 120 张合成卡片，交替使用全账户详情投影和单卡投影，跳过各自首轮预热、各测 7 次。最后一轮中位数：

- 全账户方式：11.19 ms。
- 单卡方式：5.10 ms。
- 两种方式详情 JSON 完全相同；流水投影范围由 120 张降为 1 张。

另一次相同规模运行分别为 9.24 ms / 4.19 ms。以上仅是本地合成数据 HTTP 路径耗时，不代表线上用户等待时间；未对线上网络、真实市场证据密度、OCR 或外部模型压测。

25 组结构化条件（包括中文别名、数字范围、布尔、空值、成本/汇率、持有状态）逐项与关闭 SQL 下推的原匹配路径对比，结果 JSON 一致。真实双面并发上传保留两面图片，其他账户详情访问返回 404。

## 索引核查及迁移

只读查询了当前配置数据库 pg_indexes，确认已有：

- 卡片 owner_id 索引及 owner_id / created_at 的未删除卡片索引。
- 交易 collection_item_id / transacted_at 索引。
- 估值 collection_item_id / valued_at 索引。
- 确认身份 collection_item_id / version 的部分索引。
- 复核任务的 active 状态部分索引。

新增 `db/migrations/0080_portfolio_read_indexes.sql`：

| 索引 | 目的 |
| --- | --- |
| collection_item_owner_active_order_idx | owner_id + created_at DESC + id DESC，未删除卡片的稳定分页 |
| card_transaction_first_purchase_idx | 单卡首笔 buy，按交易时间/创建时间/ID 排序 |
| valuation_snapshot_compatible_latest_idx | 排除 incompatible 后取最新估值，包含全部排序键 |
| card_identity_version_rejected_parent_idx | 按 supersedes_id 查已拒绝的撤销版本 |
| identity_research_case_item_latest_idx | 取单卡最新复核任务，覆盖所有状态 |

保留现有索引，无新唯一约束。迁移重复执行通过。仅在隔离数据库应用，当前运行数据库尚未执行此迁移。

自然 EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)，未禁用顺序扫描或强迫优化器：1,200 张合成卡、每类 1,000 条历史记录下，前三个有序查询自然使用新索引且无显式 Sort。最后一轮单次计划执行时间：

| 查询 | 补齐前 ms | 补齐后 ms |
| --- | ---: | ---: |
| 稳定分页 | 0.189 | 0.027 |
| 首笔购买 | 0.009 | 0.006 |
| 最新兼容估值 | 0.126 | 0.008 |

这些是单次合成数据计划证据，不是整体吞吐或线上提速比例。后两个索引验证了存在、定义及幂等性，未做历史密集型执行计划对照。

索引无法解决 Python 中文别名匹配、全库联合估值排序或外部模型耗时。长期全文索引/投影缓存尚未实现；本轮保持现有排序快照、最终估值和数据更新规则。
