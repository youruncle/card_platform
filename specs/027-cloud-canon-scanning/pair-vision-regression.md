# 云端正背方向和身份观察缺失

2026-10-21 用户报告多对错误，截图的 Michael Jordan 背面倒置；回看整版原图确认本批正背序号基本对应，实际回归主要是横排卡被竖转、部分卡倒置及身份观察缺失。品牌冲突用例是额外的合成对照，不作为本批错配率证据。

线上原批次 16 个区域全部 `aspect_ratio_fallback`、confidence=.25，OCR 字段全部为空。实际服务 `orientation_classifier.available=False`，OCR 配置存在但脚本文件不存在。根因：Mac 的 Apple Vision 未在 Linux 云端接通替代识别；既有配对逻辑只剩几何和颜色，不能区分同球员不同产品。

本轮最小修复计划：

1. 原生方向不可用或证据弱时，使用云端本地 RapidOCR（PP-OCRv4 英文）读文字方向，OpenCV YuNet 判断人物朝向；保留本来横排的卡面。按用户成本约束不调用视觉模型；子进程限时、限线程、沿用现有并发上限。
2. 云端观察文字复用现有保守身份提取；补充可见品牌制造商冲突，Topps/Bowman 同制造商。本地 OCR 缺失、失败或证据弱明确记入检测提示，未知身份仍需人工确认。
3. 单测先失败再通过；回放现有两张云端整版原图，检查 16 个方向、不同球员和 Jordan 两种品牌配对。相同款 Cooper Flagg 两张背面无法区分个体时保持待核对。Tesseract 已做实样本对照但因正面效果不足未进入最终方案。
4. 只叠加到实际运行 API 镜像，保留其他源码、DeepSeek 适配、搜索配置、worker=true 和已发布网页大图修复。重处理原图生成新版本，不覆盖原图或提交卡库。

## 实际实现和验证

源码 `6fa2847471816cbd713148362d3cd792544fade9`，网页/API 已发布 `0.6.3-20261021-canon3`。Linux 扫描预处理只运行本地 RapidOCR 1.4.4（PP-OCRv4 英文识别）及 OpenCV YuNet 2023mar 人物朝向；没有 OpenAI/DeepSeek 客户端调用。权重打入镜像、下载时校验固定 SHA，运行时不用联网下载。每个子进程限 45 秒、全局最多 2 个、ONNX/OpenCV 各单线程，取消回收进程组。仍沿用 Mac 原生强信号路径。

- Tesseract 对照约 26 秒/16 区域，正面文字弱；纯 RapidOCR 四旋转对照约 103 秒且竖排姓名会干扰方向，均未作为最终方案。
- 最终生产候选 `--network none` 回放现有 16 个裁图，耗时 49.54 秒；已目视核对 16 个方向，包括两张横排 Cooper Flagg、反向的 Upper Deck Jordan 正面和 Topps Jordan 背面。额外旋转 90 度的 Cooper 正面与 Jordan 背面对照也返回正确的相应方向，不固定按照片比例转动。
- 73 项相关 API 测试、166 项网页测试通过，Next.js 15.5.20 构建和类型检查通过。新增回归均先观察失败后通过；独立审查发现的“仅 OCR 失败时数据库审核标志丢失”已按真实 store_sheet 模拟持久化用例修复。
- 实际 API 原有 189 个 Python 源中 185 个保持逐 SHA 不变，只改 4 个 flatbed 文件并新增本地 OCR 文件。OpenCV headless 4.14.0 保留，没有引入 GUI OpenCV 覆盖裁切依赖。候选网页首页、10 个初始资源、Canon 延迟 chunk 和 API 代理均 HTTP 200，100 MiB 大图代理配置保留。
- 运行 API 镜像 `sha256:9b4cfcf8bcb4d01ed0c8fa387287d67581e04afba2d9c0c3f3e13facb4194388`；网页镜像 `sha256:a8f3ce9a1f7b52241b2e64b62b085264578b61843c9b6e1658bd149a7fadfc7f`。API healthy；环境文件 SHA 未变，实际 worker 环境/settings=true，既有视觉模型仍 deepseek-flash、thinking=false，搜索与视觉适配未覆盖。

从云端已保存的两张整版原图重处理，生成正面/背面版本 2，各 8 个区域和 8 条选中配对。新正面 `6db1809f-c3ab-4383-a25a-9f4e29efa77e`，新背面 `0359f9a3-e1e0-4f73-9d81-9af8e418af3b`。16 个区域均为 rapidocr_text 或 rapidocr_yunet_face，不再退回宽高猜测；每个区域保留 OCR 原文及方法。

## 局限

这批 16 个方向验证通过不代表所有卡准确率；小字、花体、品牌 Logo 仍有未完整识别的字段，8 条选中配对身份仍为 unknown。同款 Cooper 两张背面无法独立证明个体，仍需人工核对。未调用付费模型补齐字段，未代为确认/入库。未验证真实 600 DPI、API 全量测试或手机重新构建安装；本轮手机无源码变更。
