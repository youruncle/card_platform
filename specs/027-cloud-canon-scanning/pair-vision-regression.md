# 云端正背方向和身份观察缺失

2026-10-21 用户报告多对错误，截图的 Michael Jordan 背面倒置；回看整版原图确认本批正背序号基本对应，实际回归主要是横排卡被竖转、部分卡倒置及身份观察缺失。品牌冲突用例是额外的合成对照，不作为本批错配率证据。

线上原批次 16 个区域全部 `aspect_ratio_fallback`、confidence=.25，OCR 字段全部为空。实际服务 `orientation_classifier.available=False`，OCR 配置存在但脚本文件不存在。根因：Mac 的 Apple Vision 未在 Linux 云端接通替代识别；既有配对逻辑只剩几何和颜色，不能区分同球员不同产品。

本轮最小修复计划：

1. 原生方向不可用或证据弱时，使用云端本地 RapidOCR（PP-OCRv4 英文）读文字方向，OpenCV YuNet 判断人物朝向；保留本来横排的卡面。按用户成本约束不调用视觉模型；子进程限时、限线程、沿用现有并发上限。
2. 云端观察文字复用现有保守身份提取；补充可见品牌制造商冲突，Topps/Bowman 同制造商。本地 OCR 缺失、失败或证据弱明确记入检测提示，未知身份仍需人工确认。
3. 单测先失败再通过；回放现有两张云端整版原图，检查 16 个方向、不同球员和 Jordan 两种品牌配对。相同款 Cooper Flagg 两张背面无法区分个体时保持待核对。Tesseract 已做实样本对照但因正面效果不足未进入最终方案。
4. 只叠加到实际运行 API 镜像，保留其他源码、DeepSeek 适配、搜索配置、worker=true 和已发布网页大图修复。重处理原图生成新版本，不覆盖原图或提交卡库。
