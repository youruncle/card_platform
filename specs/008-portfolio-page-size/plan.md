# 实施计划
1. 为前端数量切换、筛选保留、刷新及旧请求竞争补充失败测试；为后端数量边界、分页窗口和筛选切片补充测试。
2. API 请求与响应模型上限同步到 100，默认保持 30。
3. getPortfolio 增加向后兼容的 pageSize 参数；Dashboard 用 state/ref 保持数量，复用搜索重置流程及请求版本保护。
4. 上方操作栏使用原生 select 并匹配浅色主题和窄屏布局。
5. 运行定向测试及生产构建，验证实际页面；依照本会话部署授权更新本地运行服务。

## 盈亏、检索及加载优化
1. 扩展共享排序协议及后端白名单，盈亏直接使用最终显示字段；相关度沿用全库候选顺序，在切页前排序。
2. 关键词评分与高级筛选分离：高级筛选先收窄，关键词按命中词数、字段重要性及精确程度排名；保持精确 ID 和账号边界。
3. 产品冲突检查先排除标题中不存在的标签，再进行产品族检查，只调整纯条件执行顺序。
4. 分页响应可携带账户总览，一次生成最终投影并复用；前端优先使用同响应总览，对旧接口保留回退。
5. 定向单测、隔离 PostgreSQL 接口测试、真实卡库只读计时与投影摘要对比，最后生产构建、浏览器验收、审查并重启本地服务。

6. 关键词词库仅投影所需字段，最多缓存两个公开发布版本；每次查询检查发布指针。支持按词库最长别名拆分连续中文，以及保留连字符卡号精确召回。
