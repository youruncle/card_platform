# 单卡拍卖草稿

2026-10-30。用户要求开发单卡拍卖信息准备功能，并已确认电脑点击拍照直接触发 Redmi 快门。遵循 AGENTS.md 已授权工作持续推进的要求，本次维护这一份 spec、plan、tasks，沿用现有架构和未提交成果。

## User Scenarios & Testing

1. 网页及手机卡库每张已录入实卡均有“拍卖”入口，再次打开恢复该卡自己的草稿。
2. 用户选择已有卡图，或添加新照片；电脑可连接已通过 USB 调试授权的 Android/Redmi，点拍照触发手机快门，照片自动回传。未连接、未授权、锁屏、超时须明确反馈，不能使用旧照片冒充新拍。
3. 选图后生成第一版卡淘风格标题、描述。新拍或上传后自动生成，标题和内容允许人工修改并保存，刷新或跨客户端可恢复。
4. 尝试通过已有本人卡淘订单读取接口取得标题样例，必要时读取商品详情；不可获得时说明来源不可用并使用明确的基础模板。生成只使用已确认身份，不照搬他人的品相、运费、交易承诺。
5. 调研卡淘拍卖草稿录入能力；有经核实的独立草稿接口才能实现远端保存并回读。未核实则明确不可用，保留本站草稿和复制功能，不虚报保存至卡淘。严禁发起拍卖、发布、上架、设置定时发布或产生交易。

## Functional Requirements

- FR01: 一个实卡一个可恢复的草稿；不同卡、账户相互隔离。原卡照片、身份、持仓、成本不因草稿修改而改变。
- FR02: 照片支持正面、背面、细节图，独立选择和预览，至少一张才可生成，最多12张；新照片来源可追溯。
- FR03: 草稿中保存标题、描述、人工品相备注、选中照片、生成依据和版本。并发旧版本保存返回冲突，不覆盖另一端修改。
- FR04: 草稿拍卖照片为私有资源；原图快照和新图均经当前账户与原卡归属校验后读取，不可通过公开 uploads 路由访问。
- FR05: 标题使用球员、赛季、品牌产品、卡号、平行、确知的签名/限编/评级等字段；未知字段省略或显示待确认，不补写“完美品”“保真”“1元起拍”等未确认承诺。
- FR06: 样例来自本人订单，保留商品来源和读取状态；订单样例是格式参考，不可作为当前卡身份或品相的证据。失败不阻止本站草稿生成。
- FR07: Redmi 桥接仅监听电脑回环地址，网页来源白名单、连接令牌、设备串号绑定、单次快门和新文件验证；不接收云端账户密码或登录凭据。
- FR08: 无任何真实发布接口或自动发布路径。界面清楚区分“保存平台草稿”与“卡淘草稿未接入”。
- FR09: 保留生产 purchase-cost worker=true、deepseek-flash/thinking disabled 和独立 qwen-plus 搜索配置；用户后续明确授权上线，发布网页、API及当前个人签名iPhone版，并更新本机手机助手。仍不涉及同步知识库或发布真实拍卖。

## Approaches & Assumptions

- 采用现有卡库上的独立草稿编辑器 + 现有 Canon 助手方式的本机手机桥接；云端负责草稿及私有图片。电脑直接控制 USB 手机符合用户确认的使用方式。
- 手机扫码后自行拍照不满足用户选择；直接让云服务器访问电脑 USB 不可行，因此不采用。
- 第一版使用可追溯的确定性文案模板，订单标题帮助核对格式；不引入会猜测品相的自由生成。起拍价、运费、截标时间不在本次自动推断范围。
- 实际已读本人订单并核实官方前端存在独立草稿分支；未找到经核实的卖家草稿 SDK，图片上传授权、最小载荷和状态回读仍未验证。记录真实障碍而非猜测私有写入接口。详见 cardhobby-research.md。

## Key Entities

- AuctionDraft: 当前账户、实卡、修订号、文本、品相备注、选图、生成依据、更新时间。
- AuctionPhoto: 草稿归属、照片编号、原图快照/上传/本机拍照来源、图片hash、正背/细节位置。

## Success Criteria

- 同一卡重复进入不产生多个草稿；两张卡分别编辑、重新打开后互不影响。
- 草稿新图和文案完整保存，另一账户不可读取；旧版本保存会被拒绝。
- 测试覆盖缺图、未知属性、品相备注、订单失败、并发版本、原卡删除、来源伪造、相机旧图/断连等路径。
- 验收记录逐项区分自动测试、真实 Redmi 拍照、真实卡淘草稿和生产发布；未实测部分明确保留。

## 2026-10-30 网页自动取景与手动缩放

用户明确要求网页加入自动调整和手动缩放，沿用当前 USB Redmi 助手，无需手机安装新应用。
- FR10: 网页连接后可读取真实相机倍率和取景预览；手动预设与0.1×步进经手机回读确认，不能只放大网页图片。调节不触发快门、不上传预览；切换设备、断连、关闭编辑器须取消并清理预览。
- FR11: 自动调整在本机预览中找单张完整矩形卡片/卡壳，计算保留边距的安全倍率并实际调整手机。找不到、多个候选歧义、目标贴边时明确提示，不凭空猜测、不自动拍照。偏离中心时提示移动手机；电脑不能改变物理朝向。预览为低频刷新截图，不宣称实时视频。
- FR12: 本机相机状态/预览/缩放沿用Origin、Host、client、token、serial、解锁检查和全局互斥。新版通过专用Camera2组件设置倍率并读取CaptureResult；原MIUI XML方式仅保留为研究验证，不用于生产控制路径。组件不可用时明确提示，未安装时保留原系统快门。自动识别基于macOS Vision本地矩形检测，不向云端模型发送取景。
- FR13: 允许缩放镜头实际min/max范围内的倍率，手动最高3×；当前Redmi专用组件为1–3×，预设和范围由手机回报。自动模式最大1.8×，以完整保留卡片及约10%边距为目标。高倍率会影响清晰度，结果以预览和实际回读为准。

方案：沿用已实测的MIUI相机UI变焦，使用动态XML控件与低频截图，Mac自带Vision框架本地识别矩形。专门安装Camera2控制应用会新增安装/权限流程；仅在网页缩放图片不能改变实际拍摄，均不采用。缩放不保证卡片居中，提供方向提示。

### 实机方案修订：专用 USB 相机组件（安装授权待用户确认）

系统MIUI控件的短滑动和细调实机出现忽略/跳档，不能把少数成功回读推广为稳定微调。停止将此UI自动化作为新控件生产方案；改为准备个人签名Android组件，直接使用Camera2请求倍率并读取CaptureResult确认。原系统快门能力仍保留。组件只申请CAMERA，无INTERNET/存储/麦克风；前台4:3取景、私有LocalServerSocket，电脑ADB临时转发；随机进程令牌+每请求nonce，入口要求调用方DUMP权限。新照片须与单次捕获的sensor timestamp匹配，防止超时旧JPEG被重试误用。

专用镜头范围以设备返回为准；第三方Camera2可能不开放MIUI的0.6×镜头，网页应动态显示实际min/max与预设，不能伪称支持。自动模式仍最多1.8×并检查完整边距/目标一致性。组件安装及相机权限是新增设备操作，已提出异步确认；确认前只离线编译、检查安装包与代码，不安装、不改手机权限、不把未实机的专用链路当作通过。
