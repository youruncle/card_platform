# 技术计划

沿用 FastAPI/Python/PostgreSQL 成本服务。使用独立只读审计 CLI，从当前云端已部署版本导出冻结样本、候选结果、既有订单与占用快照；不假定工作区等于线上。

1. 检查服务与 worker 开关、账户数量及缺失口径；保存基线代码摘要。
2. 使用固定 SHA256 种子、按球员/年份/产品/评级/平行/限编/既有交易/失败状态分层轮询抽样。
3. 恢复已有加密会话，仅 GET 检查和搜索；会话失效则请求用户在产品完成登录，继续缓存证据分析。不自动发验证码。
4. 原始订单按账户隔离，分别诊断搜索、召回、身份、金额、分配和写入层；按共因选择有证据的改进。
5. 测试先复现后修复；冻结证据离线回放，核对不确定状态和保护边界。

## 宪法检查
保留所有其他未提交修改；真实证据可追溯；账户隐私保留在忽略目录；无真实账本写入；不以未完成搜索宣称无交易。

## 方案取舍
优先让审计复现产品实际路径，再用更广的只读核验发现召回盲点；不通过放宽匹配提高命中。不完整查询单独标记，不与空结果混合。具体改进由审计证据决定。

## 最终实现

- DB 侧按成本身份保留必要知识：全非 card 词条、同卡号安全超集、非 ASCII 源卡号、目录元数据、关系与 artifacts。未知 Unicode 目标卡号保留全卡表。
- 四个成本知识入口共用 loader；不改领域评分与自动确认门槛。
- raw invalid order 在没有 allocation unit 时仍可进入 rejected 诊断；owner、fresh scope 和处理上限均保留。没有新增可确认金额或 unit。
- 三个工具分别冻结、已有会话清单读取/详情重试、离线分层回放。DB READ ONLY，输出文件 600，目录 700，拒绝覆盖。
- 本轮仅代码/测试/只读审计；未发布到云端、未改变 worker 开关。剩余实物与包装张数证据需求见 report.md。
