# Feature Specification: 手机 P0 功能对齐

**Created**: 2026-10-17
**Status**: Implementation authorized
**Input**: 用户授权集成已列出的全部 P0 功能。

## User Scenarios & Testing
### US1 成本查询与录入（P0）
用户在卡库或详情获取卡淘成本、重新查询、手工录入或修改价格；可绑定当前账户的卡淘账号，完成官方滑块与短信验证；候选订单须明确选择，保留金额、运费及订单快照。可批量处理所选卡片并逐卡显示成功、需确认和失败，关闭或离线不冒充后台继续。
验收：登录后继续原操作；多候选未选择不写入；失败不清空成本；已有成本批量默认保留，单卡主动查询遵循网页刷新规则。

### US2 发起估值（P0）
用户能发起/重试估值并查看排队、运行、成功、失败、证据不足。返回卡库可见新结果。验收：不重复提交运行中任务；无证据不造价；离开详情停止轮询，返回可恢复读取。

### US3 已有卡片身份管理（P0）
用户能查看候选身份与逐字段依据，选择候选或手工编辑并确认身份，必要时重新研究；复用网页审核规则。
验收：提交人工理由及字段来源；展示冲突和不确定性；不把候选自动当确认；失败保留输入。

### US4 交易与持仓（P0）
用户能切换持有/已售、记录买入/卖出/费用/调整交易并查看交易历史和估值历史。
验收：日期、币种、汇率、数量、单价及费用由用户确认，保存后读取后台计算结果；不在客户端伪造盈亏。

### US5 删除和回收站（P0）
用户可单卡或批量移入回收站、查看回收站、恢复及永久删除。验收：软删除明确确认，永久删除二次确认，批量部分失败保留失败项供重试，刷新当前卡库。

## Requirements
- FR-001：全部操作依现有登录会话与所有权规则，不能跨账户读取或写入。
- FR-002：请求禁重复提交；错误显示可操作提示；更新后卡库缓存失效。
- FR-003：沿用现有拍照、补拍、排序和搜索，不覆盖已有未提交工作。
- FR-004：不包含 P1/P2、生产部署、iOS签名发布及历史全库自动改写。

## Key Entities
现有收藏卡、身份审核与候选、成本候选与审计、卡淘账户挑战、估值任务、交易及回收站记录。

## Success Criteria
五个故事均有可点击手机入口、成功及失败路径测试；移动生产构建通过；实际外部卡淘和iPhone未验证范围明确报告。

## Assumptions
手机保持原导航：卡库承载批量操作和回收站，详情承载单卡管理；直接接入现有服务，不另建手机业务规则。用户明确授权持续实现，无需重复询问范围。
