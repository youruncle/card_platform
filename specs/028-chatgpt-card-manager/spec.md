# Feature Specification: ChatGPT 卡牌管家

**Feature Branch**: 规划阶段沿用当前分支；实施时使用 `codex/` 前缀隔离相关改动。

**Created**: 2026-10-28

**Status**: Implementing — 2026-10-28已授权按现有完整计划实施；真实连接/发布仍待验收

**Input**: 用户希望在任意手机和电脑上通过 ChatGPT 管理现有卡牌；查询、拍照入库、信息校正、买卖记账、真实成交估值、批量任务与汇总均须实现，建立持久计划逐步完成。

## User Scenarios & Testing

### User Story 1 - 查询现有卡库与组合 (Priority: P1)

用户用中文查询自己的卡片、查看正反面及交易估值历史，了解持仓、成本、估值覆盖和盈亏。

**Why this priority**: 提供最小可用入口，同时验证账号、云端连接和真实数据回读。

**Independent Test**: 用已知样本分别询问球员、签字、限编、评级、成本范围及持有状态；结果与平台同一账户一致。

**Acceptance Scenarios**:

1. **Given** 已连接自己的账户，**When** 查询“库里的签字卡按成本排序”，**Then** 返回同一云端卡库的匹配卡、稳定编号、分页和排序依据。
2. **Given** 存在未估值或异币种卡，**When** 查看组合，**Then** 分列未估值数量、币种和汇总口径，不将未知市价当作零或成本。
3. **Given** 同名或同款多张，**When** 查看“这张卡”，**Then** 用图片、编号、限编及评级消歧，未确定目标前不执行写入。

### User Story 2 - 拍照识别、校正并入库 (Priority: P1)

用户在 ChatGPT 提交单面、正反面或多张图片，查看识别草稿、核对采购信息后确认保存。

**Why this priority**: 让手机聊天成为实际新增收藏入口。

**Independent Test**: 分别用单面、正反面和三张独立卡真实图片完成上传、识别、校正和确认；在网页及手机 App 回读。

**Acceptance Scenarios**:

1. **Given** 上传图片，**When** 请求入库，**Then** 保留原图、逐卡草稿、字段证据和不确定项，展示后再确认保存。
2. **Given** 两张照片属于不同实卡，**When** 建立正反面配对，**Then** 提示冲突，不拼成一条确定身份。
3. **Given** 上传或确认超时，**When** 重试同一操作，**Then** 返回原任务或保存结果，不重复入库。

### User Story 3 - 校正信息和记录买卖 (Priority: P2)

用户修改收藏信息、记录买入/卖出/费用、移入回收站及恢复，并查看变化后的持仓和收益。

**Why this priority**: 完成日常管理闭环，写入必须与平台账本一致。

**Independent Test**: 对测试卡完成一次买入、卖出、费用、校正和回收站恢复，逐步回读；确认重试与并发不会重复记账或覆盖新修改。

**Acceptance Scenarios**:

1. **Given** 用户说“卖了1800，运费20”，**When** 记账，**Then** 明确目标、数量、币种、日期及费用承担方；先展示完整交易摘要，确认后保存并回读。
2. **Given** 身份已影响估值，**When** 修改版本/限编/评级，**Then** 沿用身份审核及重新评估流程，保留原证据和修订历史。
3. **Given** 卖出数量超过持仓、记录已更新或重复请求，**When** 提交，**Then** 拒绝非法变更或返回原结果，不生成第二笔交易。
4. **Given** 删除意图，**When** 确认操作，**Then** 首版仅移入回收站，可恢复；永久删除不开放。

### User Story 4 - 真实成交取证与估值 (Priority: P2)

用户查看既有估值证据，或为缺乏可靠估值的卡发起新研究并跟踪结果。

**Why this priority**: 复用项目证据标准，避免聊天产生无依据的价格。

**Independent Test**: 对一张有充分证据卡与一张证据不足卡实际搜索两个市场，审核捕获，分别得到可追溯估值或明确未知结果。

**Acceptance Scenarios**:

1. **Given** 新研究，**When** 完成估值，**Then** 实际检索 eBay 与卡淘历史成交并留捕获，按来源分列核图、版本、品相、日期、真实金额、原币种、运费和重复实卡审核。
2. **Given** 某来源阻塞或证据不足，**When** 回答价格，**Then** 明示真实尝试及缺口；不符合既有证据门槛的价格为 `null`，不用采购成本或经验价补足。
3. **Given** 存在旧估值，**When** 仅查看历史结果，**Then** 标记原研究日期；不得把旧证据回放称为本次新搜索。

### User Story 5 - 批量任务与周期汇总 (Priority: P3)

用户批量处理多张卡并在稍后继续查看进度，按日期和币种汇总买卖及已实现盈亏。

**Why this priority**: 在单卡流程可靠后提高管理效率。

**Independent Test**: 提交三卡批次，模拟一项失败，换设备继续查看和重试；按固定月份核对汇总与逐笔账本。

**Acceptance Scenarios**:

1. **Given** 批次部分成功，**When** 查询或重试，**Then** 展示每张卡状态、错误、成功结果；仅重试失败项。
2. **Given** 跨设备或新聊天，**When** 提供批次编号或列出近期任务，**Then** 可恢复进度；任务不依赖原聊天持续在线。
3. **Given** 不同日期边界及币种交易，**When** 请求“本月汇总”，**Then** 明确使用 Asia/Shanghai 的月份边界、原币种、折算依据及已实现/未实现区别，不混加异币种。

### User Story 6 - 可复用技能与跨设备使用 (Priority: P1)

用户连接私人“卡牌管家”，在电脑浏览器、iPhone 和 Android 的受支持 ChatGPT 客户端中重复使用相同流程，复用现有平台账户。

**Why this priority**: 跨设备是核心目标，接入可行性必须在功能开发前验证，完整验收在末期完成。

**Independent Test**: 使用实际账号完成私人安装/连接，在三类设备分别查询、图片入库及记账；其他入口回读相同结果，撤销连接后拒绝继续访问。

**Acceptance Scenarios**:

1. **Given** 已安装并授权，**When** 在受支持设备开启新聊天，**Then** 可调用已交付能力，不需要个人电脑持续开机。
2. **Given** 模糊指令或缺失字段，**When** 使用管理流程，**Then** 技能先查询、消歧、补齐信息，再按实际授权写入并回读。
3. **Given** 本地安装可用但手机未获插件或附件能力，**When** 验收，**Then** 记录为未完成并保留恢复步骤，不宣称已支持所有设备。

### Edge Cases

- 授权到期、撤销、账号切换、越权编号、私有图片访问或误选相似实卡。
- 图片过期、超限、格式错误、正反面冲突、单面证据不足和多卡图误配。
- 聊天断开、后台失败、重复提交、并发编辑、确认后摘要发生变化。
- 缺少币种/日期/数量/运费承担方；月份边界、异币种、未知汇率及空组合。
- 两市场受限、未知 Best Offer、挂牌/结束/落槌/付款含义不同及重复实卡。
- 账号不支持自定义连接或私人插件跨端分发；客户端存在版本或工具差异。

## Requirements

### Functional Requirements

- **FR-001**: 网页、现有手机 App 和 ChatGPT 必须共享同一云端卡库、账本、图片和任务结果。
- **FR-002**: 支持按球员、产品、年份、签字、限编、评级、持仓、成本及估值状态查询、分页、排序、详情与组合汇总。
- **FR-003**: 支持单面、正反面、多卡/多文件识别，保留原图、逐卡证据、采购字段和人工确认。
- **FR-004**: 支持收藏校正、买入/卖出/费用、软删除与恢复；对身份修改沿用既有审核流程。
- **FR-005**: 每次写入绑定目标和明确参数，向用户展示影响；关键写入确认后执行、回读并返回编号。重试不得重复生效；并发变更应提示重新核对。
- **FR-006**: 认证、所有权、私有媒体及读写权限必须逐操作检查；用户可撤销连接，凭证不进入聊天、技能包或日志。
- **FR-007**: 新逐卡研究必须真实检索两个指定市场、留捕获并按既有研究合同审核；证据不足价格 `null`；历史与新研究分开标记。
- **FR-008**: 耗时工作在云端持续运行，返回任务编号；支持近期任务、逐项状态、部分失败和有限重试。
- **FR-009**: 支持按明确时区/日期区间/币种查看买卖、费用、已实现盈亏及估值覆盖，不使用模型心算替代账本统计。
- **FR-010**: 提供可重复使用的管理流程与实际可安装的私人接入，先验证账号权限和三端可用性；只报告实测通过的设备和功能。
- **FR-011**: 维护一份开发任务清单，按阶段记录完成证据、外部阻塞和下一动作；规划完成不等于功能完成。
- **FR-012**: 首版覆盖上述全部管理目标；不包含自动下单、代付款、公开交易市场、永久删除和默认定时自动写入。
- **FR-013**: 保留现有未提交修改及既有架构，知识库迭代仅面向云端；不得借接入修改真实历史卡库或伪造识别、搜索及测试结果。
- **FR-014**: 发布保持自动成本 worker 开启，云端视觉保持 `deepseek-flash` 且显式关闭 thinking；独立 `qwen-plus` 搜索使用原百炼端点及独立凭证。
- **FR-015**: 本功能要求认证隔离、写入幂等/并发、真实图片、成交证据和跨设备端到端回归；未运行项和缺失样本明确记录。

### Key Entities

- **账户连接**: 用户对卡库的授权、权限范围、有效期与撤销状态。
- **收藏与交易**: 沿用既有实卡、身份版本、原图、持仓、费用和交易账本。
- **待确认操作**: 目标、参数摘要、数据版本、有效期、确认及执行结果。
- **后台批次与任务**: 所属用户、逐项进度、错误、重试及最终结果引用。
- **市场研究**: 身份、检索尝试、原始捕获、逐条审核、估值与证据缺口。
- **技能及能力版本**: 已交付工具、工作流程、版本及跨设备验收记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 预置12条查询/详情/组合请求，结果全部与同账户平台数据一致，跨账户访问全部拒绝。
- **SC-002**: 单面、正反面、三张独立卡、多卡图各至少1组真实样本完成入库；每组重复提交3次仅生成一次结果，保留不确定字段。
- **SC-003**: 买入、卖出、费用、校正、软删除及恢复六类操作均保存并回读成功；重复和并发用例不出现重复账或丢失新修改。
- **SC-004**: 至少2张真实卡完成新研究，两市场均有实际尝试捕获；证据不足样本价格为 `null`，可用结果可逐条追溯。
- **SC-005**: 一个三卡批次在断开聊天后可恢复，部分失败不重复执行成功项；一个固定月份报表逐笔核对一致。
- **SC-006**: 电脑浏览器、iPhone、Android 三类实际设备分别通过查询、图片入库、记账与撤销访问；缺设备或权限时保持验收未完成。
- **SC-007**: 每一勾选任务均关联验证命令、实际结果或可访问捕获；没有开发任务仅凭计划文字标记完成。

## Assumptions

- 首版为用户本人私人使用；保留账户隔离，为他人提供服务及公开上架不纳入此次范围。
- 手机和电脑联网并使用拥有所需权限的 ChatGPT 账号。账号能力、私人分发及附件传递作为前置实测事项，尚未证实。
- 目标是不依赖本机常开；现有云端服务继续提供识别、账本和后台任务。
- 确认预览和操作有效期等技术默认值在计划/合同规定，属于实施建议，可随用户反馈调整。
- 2026-10-28后续请求已授权按完整计划持续实施及发布；生产账号连接须由用户完成必要授权，真实收藏写入仍遵循具体预览/确认及测试范围约束。
