本轮冻结100张没有交易记录的互异库存卡，并为每张找到当前账户已完成订单里的一个互异购买行。79张不在此前30例内，21张用于旧例回归。订单存在并不代表候选一定同版：人工逐一查看正背面及必要商品原图后，76张支持同款、5张双方完整流水号相同、9张版本仍待确认、9张明确不同版本、1张卡库正背关联异常。未编号同款还须通过完整竞争域、金额和可分配单元检查。

私有逐例证据、订单标识与照片保存在 `.runtime/cost-audit-100-20261019/`，不纳入公开规格。`report100.html`提供100例图像与阻断对照，`report100.md`提供逐例索引。图像缩略图记录原始源哈希和实际模型输入哈希；离线正证不会注入线上。

## 读取与结论边界

本轮读取当前订单列表212条、7页，新读取196条已完成订单详情；100个目标购买行全部包含其中。另8条更早订单未在本轮完成详情重读，不能声称完整遍历所有历史详情。离线对196条详情做关联召回，也不能声称完成了100次在线关键词搜索。141个商品画廊集合含485张商品图，画廊通过精确购买商品URL及订单主图共同绑定；模型使用目标正背与商品多图，人工补看裁图遗漏的背面、完整评级盒和不同平行细节。

历史首次失败没有每例完整调用日志，因此逐例结论指当前版本可复现的阻断，不能断言历史首次失败均由同一原因造成。

## 已复现原因

| 环节 | 本100例发现 | 含义 |
|---|---:|---|
| 自动调度 | 初始100例均无自动任务记录 | worker开启不自动为旧库存补建任务；旧卡需主动重试获取成本 |
| 订单缓存 | 100个目标订单均已缓存 | 不是这100个候选完全没有订单来源 |
| 文字识别 | 12例文字规则可通过 | 仍需金额与可分配单元；其余卡存在平行、Insert、限编或身份字段缺口/冲突 |
| 多图旧版回放 | 1同款、93不确定、2不同、4格式失败 | 同款判断仍不是成本录入结果 |
| 旧版固定表面门槛 | 44例停在此处 | 首轮表面未知不会触发独立表面补证，造成无法继续复核 |
| 旧版评级门槛 | 28例停在此处；其中24例含印刷文字误作评级 | PRIZM、品牌或版权文字被塞入grade/grade_cert；真实评级差异仍需阻断 |
| 存储卡号冲突 | 13例停在此处 | 必须核对库内身份或OCR；不能为成本覆盖真实身份 |
| 金额/分配 | 7例金额有错误，7例缺少目标单元 | 部分是整包数量、优惠/差额或运费依据缺失；两组可重叠，不能假定零运费 |
| 历史核验总闸 | 2例 | 仍需覆盖完整候选范围，不能清空总闸强行匹配 |

另有产品/赛季冲突、串号冲突、球员/正背关系未确认和真实不同版本。9个不同版本及正背异常均作为负例保留，不计作应追回成本。

## 改进方案及已实现范围

1. 将品牌、产品、赛季、球衣号和比赛比分设为独立字段。用中文明确字段语义，禁止把品牌/版权当评级，把球衣号当卡号，把比分当限编。无效字段至多重读一次，并保留私人诊断及原观察。
2. 重读不能删除或改变其他有效证据。按同一Pydantic模型规范化字段、别名、布尔值及图片分类；保留串号原文、照片归属、评级证据和既有设计/表面/球员冲突。不能通过删字段、改成广告或把different改unknown获得正证。
3. 只有卡号、串号、球员、正背、评级等前序门槛通过且首轮设计相同、表面未明确不同时，才允许独立上下文补充表面证据。保留首轮unknown，不改写为模型首轮same；独立正证绑定当前身份、购买行、订单哈希和每张图片。
4. 对软缺失的未编号卡，允许双侧印刷清单卡号、完整前序门槛及独立固定表面正证支持同款，不强迫卡面印出官方平行名称。真实限编、产品/赛季、评级及数值冲突仍阻断。财务、所有权、竞争域和购买单元唯一性规则保持执行。
5. 单次成本服务操作内复用同连接、同投影的知识库解析器，退出/异常/取消后清理。ContextVar同时绑定当前任务，防止子任务、账号或下次操作复用旧快照。没有建立全局缓存。

本轮没有修改自动任务的历史回填政策、整包分摊/财务政策，也没有覆盖卡库身份。这些仍是未追回案例的后续处理方向，不能把模型正证当作全部问题已解决。

### 线上首轮事实补充

新版本顺序实际尝试A033、A041、A094、A082：A082通过正常服务提交了购买交易；前三例没有写成本。已确认不是同一种原因：A033/A041把正在多图复核的自身单元同时标为弱竞争者，造成正证也会被降级；三例均在公开HTML读取阶段遇到默认httpx请求头被服务器重置。单变量实验验证仅更换为现有CardHobby公开请求UA即成功，TLS校验、精确商品、主图绑定和CDN原图哈希均通过，无需更换域名或跟随跳转。两处最小修复及防回归后，相关隔离成本测试516项通过，随后已再次发布和真实重试，结果见最终统计。

另外对A014/A015/A021/A024使用原有成本功能重试，四例均返回两笔同款购买供选择，没有自动写入；这是实物对应关系尚不唯一，不能计为识别失败或替用户强选订单。A082走既有文字匹配路径，不能将其成本恢复归因于新多图算法。

### 运行事件与局限

后续图像协议改进采用同一100例初轮回放、仅对已明确的格式/语义错误或受保护重读变化做一次定向复读，再用最终规则重算100例。模型实际运行顺序、原输出、失败及阶段代码哈希都保留；不会把这批开发回归声称为独立准确率盲测，也不会把same数量当作成本追回数量。

## 最终结果（2026-10-19）

- 同一冻结100例完成初轮前后回放；60例按预定协议/语义错误规则额外定向读取一次，选择规则及所有阶段原输出均保留。最终规则重算100例，未为了寻求same重复读取已有效负例。
- 离线身份关联门槛通过 **13 → 31**：原有12例文字通过保持，图片证据支持的升级 **1 → 19**。这19例包含17例人工同款支持及2例双方完整同流水号，15例不在此前30例内。**没有将31例当作31笔成本写入**；完整线上竞争域、金额和购买单元仍另核。
- 9个明确不同版本及1个正背关联异常共10个负例，最终自动身份通过 **0**。最终模型原输出39同款、58不确定、1不同、1格式失败、1API超时；模型标量结论也不直接授权成本。
- 对10张互异卡使用正常线上获取流程：**2张实际入账（A082、A094）／4张需选择两笔同款购买／4张仍未通过**。账本前后差集准确对应A082、A094；A043在本补丁前已由另一发布恢复，不计本补丁收益。100例外的旧30例C03另由原有功能补回1张。
- A082走既有文字路径，不能归因于新多图算法；A094经新多图/同流水号流程正常提交，是本轮验证到的多图实际入账收益。
- A033仍因独立表面核验将反光/颜色差异判断为固定色差而未入账；A041存在另一未核验竞争购买行及格式失败；A018完整搜索后图片候选超预算；A062独立表面证据仍未确认。没有强行选择或降低正证门槛。
- 生产临时核验改为同一已验证应用镜像的隔离执行容器，沿用相同正常服务、账户、数据库及校验，避免其他发布重建API反复中断；它不是新增常驻服务或第二个worker，完成后自动移除，临时环境文件已删除。

后续改进优先级：

1. 将完整候选场域核验改为持久化分段任务，小步保存每个候选的结果与阶段证据，未全部核验不得自动写；覆盖超过6个候选，以及两次观察加独立复核超过90秒的情况，避免整段事务回滚丢进度。
2. 对同流水号但表面颜色不确定的案例，继续用真实反例控制集改进反光、固定色及纹理的区分；不能以同模板或串号相同直接覆盖不同平行结论。
3. 将真实字段冲突与不确定OCR转成带图像证据的人工确认；先核实卡号/正背关系再重跑成本。对多笔同款购买保留选择，对缺少金额/整包数量依据的订单保留财务阻断。
4. 给历史无成本卡提供显式、可限量、可续跑的重新获取入口；worker开启本身不会追溯建任务。本轮没有对全账户强制重排或批量改写身份。

手机为实体设备不可用，已安排本线程heartbeat在连接后继续个人签名渠道覆盖安装、核版本与启动；未连接时静默，禁止用旧验证包降级更新客户端。本次成本变更位于云端，手机现有成本功能使用新API。
