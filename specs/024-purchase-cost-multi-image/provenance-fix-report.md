# 采购来源约束增量

完整100张逐卡执行到第31张时，发现已保存来源商品的原订单因财务差额不可分配，另一笔同款订单因此被当作唯一候选写入。批次安全停在入账后复核门，生产worker保持开启；实际异常交易保留并从已复核成本成功数中排除。

用户确认修复：明确声明的采购来源约束归属，不能用其他同款替代原来源的财务缺口。实现将来源阻断独立于身份匹配，放在图片/整包推断之后的统一候选入口，实际确认会重新核验该入口。无来源卡片保留原正常匹配；普通参考、图片、估值链接不被当成采购来源。不会更改原始订单、库存身份或既有交易。

隔离PostgreSQL原始回归3失败/1通过，复现了财务受阻或来源缺席时错误写入另一同款，以及有有效来源时仍要求选择另一同款。修复后购买成本相关测试688通过，Ruff四文件通过。独立审查发现参考来源标签误拦，新增四例先复现失败再修复，最终复审未发现该范围内剩余重要问题。另有5项私有驱动复核门测试通过：仅已获用户授权、绑定实际异常来源且对应新源码守卫的隔离记录可接续，不创建虚假复核通过标记。

尚待：将两模块补丁叠加到实际线上版本、确认实际导入源码及worker/Flash原生非思考，再从第32张接续剩余69张。前31张原结果保留，不重跑；实际异常保持单列，全部100结束后完成账本、身份、重复单元、10个负例及失败归因审计。
