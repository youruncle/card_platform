# Feature Specification: 卡淘估值覆盖率与证据质量优化

**Feature Branch**: `codex/cardhobby-valuation-quality`；保留原工作目录全部既有修改  
**Created**: 2026-09-21  
**Status**: Approved — 已授权分轮实施；全部验收通过后直接批量写回  
**Input**: 对当前账户未估值、证据不足、疑似价格异常及正常对照卡开展只读评估，提高合理估值覆盖率，降低错卡与价格偏差；仅使用卡淘。Spec Kit 与 Superpowers 共用本目录的 spec、plan、tasks。

## User Scenarios & Testing

### User Story 1 — 看得懂且能复现的基线 (Priority: P1)

账户持有人可以区分“从未有价”“当前证据不足但保留旧价”“当前有有效估值”，并查看每张卡的身份、候选、来源、失败环节及资源开销。

**Why this priority**: 没有稳定分母、证据版本及成本口径，就不能声称优化有效。

**Independent Test**: 相同冻结文件重复汇总得到相同卡数、分层、来源集合；缺少的时间/费用必须显示未知，不能显示零。

**Acceptance Scenarios**:
1. Given 旧估值存在但最新任务证据不足，When 汇总覆盖率，Then 计入证据不足，旧价格单独列出。
2. Given 来源获取失败，When 查看失败环节，Then 区分网络失败、零结果、候选拒绝、未执行及历史记录缺失。
3. Given 审计运行，When 比较前后状态，Then 不新增生产估值、任务、身份修改或采购成本回填。

### User Story 2 — 独立证据复核与参考区间 (Priority: P1)

持有人能查看原卡正背面和候选商品图、标题、详情的具体匹配与冲突依据。只有证据足够时才产生参考估值区间。

**Why this priority**: 旧模型的“same”或 OCR 结果不能自证正确；减少证据不足不能牺牲同款准确性。

**Independent Test**: #97 清单中的203不被当作卡号；#486 的 GR-5 不引用基础卡紫折；#383 的星形纹理候选不因同构图被当作同版；#135 新召回的53元记录不能单独变为公允价。

**Acceptance Scenarios**:
1. Given 相同球员、限编但不同构图/特卡，When 比较，Then 判不同卡且排除定价。
2. Given 单条、缺背面、品相无法比较或支付状态不明，When 建立参考，Then 明示证据级别和限制；不足时区间为 null。
3. Given 已结束且有出价的拍卖，When 记录价格，Then 称落槌价，不称已付款成交；人民币卡价和运费分别记录。

### User Story 3 — 可验收、可分轮的优化 (Priority: P2)

持有人先确认共性根因、验收标准和每轮范围，再决定是否进入离线实现、影子评估及生产发布。

**Why this priority**: 先用同一固定样本集验证原因，再实施最小改动，避免批量反复改价。

**Independent Test**: 每轮有输入样本、失败复现、对照、通过条件和退出条件；不能用未判定样本计算价格准确率。

**Acceptance Scenarios**:
1. Given 召回方案，When 同预算比较，Then 报最终合格同卡证据数、可判定覆盖和错卡率，不用搜索结果数替代。
2. Given 门禁或校准变更，When 回归，Then 同款身份、评级、版本、成交状态、品相硬冲突仍不可绕过。

### Edge Cases

- 页面不可访问、图像404、反爬、超时、缓存与线上返回不一致、仅搜索摘要或评价打包价。
- 年份是统计赛季/版权；卡号是球衣号码/名单序号；同形异码姓名；缺失与明确否定混淆。
- 同限编不同平行、反光变化与固定纹理区别、套卡、多人卡、评级/裸卡、交换板。
- 单次1元落槌、一次出价、多次上架同一实卡、商品ID重复、运费超过卡价。
- 当前身份、已确认身份、扫描识别和估值使用的身份不一致；旧视觉结果绑定旧图。

## Requirements

### Functional Requirements

- **FR-001**: 仅评估当前账户未删除且未处置的卡；保存冻结时点、版本和内容哈希，保留原有未提交文件。
- **FR-002**: 分别记录当前有效状态、历史快照、从未有价；全量自动盘点，固定分层抽样独立复核，明确抽查范围。
- **FR-003**: 每卡记录存储身份、估值实际使用身份及来源；记录原图、候选图和字段位置，未知字段不得推断为确定事实。
- **FR-004**: 七段链路分别记录输入、输出、执行/失败状态、来源链接及拒绝原因；保存未通过的候选，允许多原因并存。
- **FR-005**: 记录总等待时间、执行时间、阶段耗时、模型调用次数、usage、费用币种及定价版本；历史缺失明确标记不可回填。
- **FR-006**: 参考复核须独立于旧估值结论，分别比较图片、标题、详情及成交事实；不具备条件时为无法判定，不以旧价、采购价或模型猜价补足。
- **FR-007**: 只用卡淘商品级证据，逐条区分付款确认、已结束有出价拍卖、挂牌、无出价及未知。评价打包价、摘要不能作为单卡价格。
- **FR-008**: 参考区间与系统输出分离；同款但缺少足够价格证据时只记录历史观测值。稀疏证据不能伪装成精确价格。
- **FR-009**: 优化不得仅放宽门禁，不得使用采购成本，不得编造价格；来源、身份、版本、评级、套卡和品相冲突必须保持约束。
- **FR-010**: 根据实证影响范围排序根因，区分已证实、代码结构风险及待检验假设；任务映射样本与验收。
- **FR-011**: 同一测试集包含正常、异常、无法判定样本，按实卡身份分组划分开发/保留集，防止近重复泄漏。
- **FR-012**: 按已批准任务实施；先保存新旧影子结果，不覆盖正式估值。全部已确认验收标准达到后直接批量写回；不需要重复批准。关键需求变化、权限或额外预算另行确认。

### Key Entities

- 基线卡：账户内卡片、身份版本、当前状态和历史估值。
- 来源记录：卡淘商品、图片与详情版本、价格/出价/结束时间、获取情况。
- 阶段记录：一次运行中某一步的输入、判定、耗时、费用与证据指针。
- 独立复核：可见字段、匹配理由、参考区间或无法判定理由。
- 固定测试集：分层样本、开发/保留分组与验收结果。

## Success Criteria

以下为用户已确认的验收门槛，不是本轮已达到的性能成果。

- **SC-001**: 基线覆盖冻结账户100%在库卡；100%样本有状态、历史价、证据和缺失原因。相同冻结文件汇总完全一致。
- **SC-002**: 首轮固定60张评估样本，覆盖20张从未有价、20张有旧价但不足、10张疑似风险、10张正常候选对照；所有60张完成原图及可获取候选独立复核，不能访问也有明确记录。
- **SC-003**: 在冻结的可判定集上，合理估值覆盖率较基线提高至少10个百分点，且已知错卡引用为0、正常对照合理覆盖不下降；若可判定卡少于20张，只报告数量，不宣称总体提升。
- **SC-004**: 参考区间外相对距离的中位数≤15%、P90≤35%；同时报告区间重叠率、区间宽度和样本数。无法判定者不进入价格误差分母；参考区间不能为了容纳系统价格而放宽。
- **SC-005**: 关键错卡反例、零出价/挂牌/套卡/评级冲突及采购成本污染反例100%守住边界；新增候选判定100%绑定图片和来源版本。
- **SC-006**: 新影子运行100%记录阶段耗时及模型usage或明确缺失原因；费用账本缺失时不宣称成本改善。同等证据与缓存条件下，每卡成本及执行P95均不高于基线1.2倍，例外需说明收益并另行确认。
- **SC-007**: 评估与影子运行对生产估值、身份与任务零写入；原有范围外工作文件哈希保持不变；范围内增量以执行前备份为基准核验。

## Assumptions

- 当前唯一有在库卡的账户即本轮账户；若后续出现多个账户，导出应停止并要求明确账户，而非合并。
- “未估值”独立定义为从未存在快照，同时属于当前证据不足的子集；不存在最新任务的卡另外列出，不重复计算总数。
- 以冻结时点为准，价格为CNY单卡不含运费；90天近期窗口，91–365天仅历史参考，超过365天另列。低流动性卡不能用时效放宽掩盖缺证据。
- 充分参考区间默认至少3个去重且可核实同款/同评级/可比品相拍卖、至少2个卖家、90天内；证据不足继续为未知。这是验收标签标准，不在本阶段修改现行生产稀疏证据政策。
- 卡淘付款无法确认时，允许建立明确标记的“公开落槌价参考”，不声称实际付款价值。模型意见不是 ground truth。
