# 程序化实卡采集V1（2026-10-23）

本轮用户批准后台批处理第一版。沿用spec/plan/tasks的US8与T048–T051；程序交付与知识内容覆盖分开验收。

## 已实现边界

- `scripts/knowledge_intake_worker.py`：init / run / report / review / export。
- 云端已发布清单与附件SHA冻结；产品轮转选取试点，保留全部卡款身份及原始来源定位。只认可明确的具体卡款面别覆盖，不把产品样图或section级候选当成准确版本已补图。
- PostgreSQL五张独立表：批次、任务、执行尝试、候选、审核事件。租约过期恢复、旧租约拒绝完成、三次有限重试、阻塞不空转、初始化幂等且拒绝变更冻结范围。
- 卡淘公开实卡来源：实际搜索/商品图库/原图字节、逐请求回执、限速、大小限制及域名边界。HTML200空壳不当无结果；链接、下载及身份确认分别计数。
- 审核输入绑定候选hash、每张图片hash/角色/观察和冻结身份。审核通过后可导出单面；发布校验重放原始图库、审核与清单关系。新`reviewed_unpaired_public_image`合同不允许配对主张，保留原认证/限编号配对合同。
- 导出ready资产用于既有向量/发布流程，不直接发布知识；本版没有内置大模型/OCR自动审核，没有后台常驻调度或管理页面，不声称全自动身份审核已实现。

## 实施裁定

- 当前目录包含必须复用的未提交模块，原地增量增加文件，不stash/清理/覆盖其他工作；不自动提交用户既有工作。实现期间其他会话提交了已有知识资料及spec调整，保持其内容与FR39–FR44编号。
- 线上API资料目录为只读。独立一次性worker沿用当前API镜像、只读正式知识附件，只把本批目录作为可写子挂载；云端PostgreSQL保存队列。首次尝试在API容器内创建目录遭只读拒绝，未改挂载。首次独立worker因批次目录所有权遭权限拒绝，修正指定批次目录的UID/GID后重试；不开放整个资料目录。
- V1先完成采集与审核桥接；知识封版仍须执行SOP三类来源路线、所有候选处置及真实云端回读，本试跑不能据此报告知识录入批完成。
