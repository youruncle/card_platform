# Published knowledge browser — 2026-10-22

User approved the directory/details/gallery proposal and authorized implementation in this chat. Reuse this feature's spec, plan and tasks. All routes are read-only and preserve the existing administrator authentication boundary. No deployment, new knowledge collection, business-data mutation or AI model changes are included.

Types: `packages/card-core/src/knowledge-browser.ts` is the shared response contract. Routes live under `/v1/knowledge/browse`. Lists use `{items,total,offset,limit,version}`. IDs are opaque strings; encode path IDs with encodeURIComponent. All list limits are 1..100; offset >= 0. Optional `version_id` pins requests and media to the immutable knowledge snapshot returned by summary.

- `GET /summary`: KnowledgeBrowserSummary, all published manufacturers (including those without products), seasons, type counts and honest source errors. Counts are known published content, never exhaustive coverage percentages. Card facts include immutable attachments and entity cards, deduplicated by card ID.
- `GET /products?manufacturer=&season=&q=&has_images=&offset=0&limit=24`: KnowledgePage<KnowledgeProduct>. season means season_start; q includes canonical names and reviewed aliases. Unassigned manufacturer/season remains unknown.
- `GET /products/{id}`: KnowledgeProductDetail; section and parallel facets come from proven card rows, never synthetic combinations.
- `GET /cards?product_id=&manufacturer=&season=&q=&section=&parallel=&image_state=any&offset=0&limit=40`: KnowledgePage<KnowledgeCard>; q includes player, card number, product, aliases and section. image_state is any/has_image/missing_front/missing_back. Design samples do not satisfy card-image filters.
- `GET /cards/{id}`: KnowledgeCardDetail; same product/year/player/card-number/section versions only, capped at 30. Images must have an explicit card binding; no guessed side/pair/version.
- `GET /media?product_id=&card_id=&kind=all&offset=0&limit=24`: KnowledgePage<KnowledgeMedia>; kind is all/design/specimen. Preserve unknown-side images. Exclude private and unreviewed media. Optional product_name/manufacturer/season_start/season_end describe the published parent product for gallery navigation; absent metadata stays unknown.
- `GET /media/{id}/image?thumbnail=false&version_id=`: authenticated locally captured images, original checksum checked, only paths referenced in the selected snapshot. Browser-native JPEG/PNG/WebP/GIF return captured bytes; JPEG2000/TIFF/BMP/MPO are rendered as a full-resolution JPEG display derivative, preserving original files and hashes. thumbnail=true creates a bounded display derivative. Never accept arbitrary paths or proxy external URLs. Missing bytes return 404, corruption 409.
- `GET /entities?entity_type=&q=&offset=0&limit=40`: KnowledgePage<KnowledgeGlossaryEntry>, published knowledge and aliases, not workspace drafts.

Web sends cookie-authenticated requests through existing API helper and assetUrl. Mobile uses api.get and api.image (authenticated Blob/object URL, revoke on replacement/unmount), never unauthenticated native image requests. Abort or ignore stale requests. Switching search/filter resets pagination; product/card navigation preserves the catalogue context. Clearly distinguish empty/error/loading, unknown fields, design samples, card images and actual front/back pairs.

Web `/knowledge` becomes the browser; existing page moves intact to `/knowledge/manage`, with a back-link. Both clients expose catalogue, cards, gallery and glossary; product detail exposes overview, cards, section/parallel knowledge, images and sources. Images support side switching, rotation/zoom and comparison using only actual captured images. Mobile supports full-screen viewing and returns to preserved filters.
