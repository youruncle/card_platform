# 云端知识录入模块设计

状态：2026-10-22设计交付；本次执行现有采集/审核/云端发布流程，不声称本模块已实现。沿用本目录唯一spec/plan/tasks，配套操作规范为 `docs/knowledge-intake-sop.md`。

## 目标与范围

管理员按厂商、运动和赛季冻结年度产品范围，持续采集文字和图片，审核后发布到云端，并在同一入口看到真实进度与缺口。系统负责记住每个产品做到哪一步、保留证据、阻止漏项发布；不能依靠聊天记录或管理员手工“认为完成”。不读持仓决定采集范围，不修改估值或用户私有卡图。

本次近三年任务继续以2023/2024/2025起始年、126个已知产品为冻结范围；53个缺图产品必须逐项完成来源路线与候选处置。年度产品母集穷尽、所有卡片的所有版本实物图齐全是另一个更强目标，分母尚未确定时不能显示100%。

## 方案选择

| 方案 | 收益 | 局限 | 结论 |
|---|---|---|---|
| 脚本加人工台账 | 最快复用现有采集工具 | 中断恢复、责任、审核与发布状态仍分散 | 本轮执行工具，配硬校验 |
| 云端批次工作台与持久队列 | 单一主库、可恢复、每产品可追溯，能强制封版条件 | 需要新增工作流与管理界面 | 推荐后续模块 |
| 大规模全自动站点爬取与自动认定 | 理论吞吐高 | 不同站点/赛季/图片语义差异，难保证身份与冲突正确 | 作为适配器逐步扩展，不先做无人审核系统 |

## 工作台信息架构

1. 批次页：冻结范围、来源策略版本、当前云端基线、负责人、目标维度；醒目显示未搜索、待审核、可用未发布、外部阻塞和云端复验失败数量。
2. 产品队列：按年度/厂家/任务步骤筛选；每行展开官方身份、文字/设计/卡面/背面/配对/向量分别的覆盖，不能用一个绿色“完成”吞掉部分覆盖。
3. 来源页：已执行查询、实际结果、原文与原图、捕获方式、访问失败；可打开证据定位和重试，不把错误HTML当成功文档。
4. 审核页：文字字段的来源对照、不同赛季命名、图片原图与正反面、官方清单候选集合、冲突与拒绝理由。批准产品设计参考与确认具体实卡是不同操作。
5. 发布页：只显示本批将增改的事实/来源/图片及索引；列出基线差异、受保护内容和阻断项。封版、发布、复验逐步显示结果，不把上传成功当发布成功。
6. 缺口页：外部来源阻塞、来源缺行、官方冲突、未知年度与未来发现分别列出；下一次恢复时从原步骤继续，不能重新从零或静默跳过。

## 状态与完成语义

任务步骤为queued→discovering→capturing→parsing→reviewing→ready→published→verified。失败进入retryable_failure或evidence_gap，保留原步骤、原因与恢复动作；租约过期回到原步骤，不能变成成功。reviewing状态只能通过明确审核决定退出。

独立记录每个维度的not_started/partial/verified/external_gap/not_applicable，以及已知/未知分母。图像向量完成不提升图像覆盖；一张正面不提升背面或配对覆盖；下载设计资料不产生实卡身份。

批次运行状态open/ready_to_seal/sealed/publishing/published/verifying/verified_with_gaps/verified_complete/failed。verified_complete只适用于冻结目标的全部维度已满足且没有内容缺口。所有必需工作已处理但存在有证据外部缺口时使用verified_with_gaps，界面写明“本批已处理，仍有N项内容缺口”，不能写“知识已齐”。存在queued、待审核或可用未发布资料时，两种verified状态均不允许。

## 数据与已有能力的边界

| 记录 | 关键数据 | 与现有系统关系 |
|---|---|---|
| IntakeBatch | batch_id、scope、cutoff、scope_hash、policy_version、expected_cloud_checksum、目标、负责人 | 工作流对象，区别于现有已应用manifest的knowledge_import_batch |
| IntakeProductTask | source_key、任务步骤、维度状态、租约、attempt/review数量、阻塞与下一步 | 一产品一范围任务，来源身份不由持仓反推 |
| SearchAttempt | 类别、真实query/URL、时间、结果、capture_id | 查询本身也有证据，不以checkbox替代 |
| SourceCapture | 原URL/实际URL、类型、方式、时间、SHA、字节、原始位置、权威层级 | 不可变来源附件，复用现有知识来源模型 |
| FactClaim | 原始字段、规范字段、source_locator、身份范围、冲突组、审核决定 | 官方事实与第三方主张分开，发布时映射现有实体/附件 |
| MediaAsset | 图片字节/位置/SHA/尺寸、产品/面别/类型、候选身份、source_capture、审核依据 | 公共参考和私人资产边界明确；不接收任意外链作为已取得图片 |
| MediaPair | 两面asset_id、同实物证据、身份候选集合、审核决定 | 单独关系；相邻图库图不自动配对 |
| EmbeddingGeneration | model/revision/预处理、维度、输入SHA、记录数量、index_hash、知识批次 | 可重建派生索引，现有学习向量能力复用 |
| ReviewDecision | 谁/何时/对象hash/决定/理由/所依据版本 | 改字节或候选后原审核失效 |
| IntakeReleaseCheck | 门禁结果、manifest_hash、索引hash、版本、实际云端复验收据 | 关联knowledge_import_batch/knowledge_version，保留重放与回滚 |

云端PostgreSQL保存任务和审核账；不可变文件/对象存储保存证据与媒体；现有knowledge_version承载已发布事实。浏览查询缓存和向量缓存都是可删重建的派生物，不能成为另一个主库。正常线上查询不加载大型编码模型。

## 工作执行

来源适配器只负责发现、下载、解析与定位，不负责自行批准身份。按厂家/资料站/认证图/原厂转载分类，明确每站分页、格式和限速；保持每主机并发限制与可恢复失败。受阻来源留证后切换适配器，不循环重试403或绕过验证码。

队列支持批次/产品级租约、心跳、重试次数、退避、幂等键及内容缓存。可并行的产品互不改同一任务；同产品的下载、审核、封版顺序执行。编码工作独立进程或受控任务运行；本机可作为暂时编码工具，但结果必须传回云端验证，不能写本地运行知识库。

抓取入口限定经过审核的来源适配器与公开HTTP(S)资源，不提供任意地址代理。账户权限沿用现有管理员知识管理权限；来源捕获与审核写入有审计，普通浏览只访问已发布资料。任何用户私有照片需要显式账户授权，不能自动升级为公共知识。

## 建议接口合同（待实现）

入口沿用管理员知识路由下的`/knowledge/intake/`。批次创建冻结scope和expected_cloud_checksum；批次/产品列表分页并返回各步骤数量。来源尝试、捕获、事实、图片、审核分别有独立对象，不通过一个“导入完成”按钮跳过中间状态。

- `POST /batches`：创建冻结范围和策略，返回batch_id、scope_hash和全部任务数。
- `GET /batches/{id}`、`GET /batches/{id}/products`：真实队列及覆盖统计；不能把无证据failed计作已处理。
- `POST /products/{task_id}/retry`：指定原因与恢复步骤，保留历史；不能重跑覆盖审核事实。
- `POST /captures`、`POST /claims`、`POST /assets`：提交捕获结果与字节/定位，做哈希和身份范围校验。
- `POST /reviews`：针对不可变对象hash批准、拒绝或保留冲突；审核后改内容必须再审。
- `GET /batches/{id}/release-preview`：展示差异、保护对象、索引关联和全部阻断项。
- `POST /batches/{id}/seal`：强制完成条件，输出不可变manifest/index/ledger摘要；失败逐项返回，不允许前端强行忽略。
- `POST /batches/{id}/publish`：预期云端checksum、幂等键及封版hash必填；原子发布当前批次，其他内容不变。
- `POST /batches/{id}/verify`：实际云端回读检查，生成收据；失败不进入已验收状态。

创建、重试和发布请求都携带明确幂等键。发布时若云端版本已改变，返回baseline_changed并要求重新比较/合并；不自动把旧完整产品属性覆盖到新版本。并发发布使用现有知识发布互斥。重复同一封版请求返回原版本，不创建重复知识。

## 封版与发布门禁

必须同时满足：冻结范围每项有处置；必需来源路线的真实捕获完整；所有候选均已批准或有理由拒绝；所有已批准事实/图片都进入manifest；必需图文向量完整且输入hash一致；未搜索、待审、可用未发布均为0；外部缺口有实际尝试和恢复动作；所有来源/媒体/审核/清单checksum有效；本批产品身份与基线一致；旧人工/其他来源事实不会改变。

发布后检查实际知识版本与source/index标签、全部文件可读取和hash、图片面别/配对、各年各厂商卡号正例与错年/品牌/子品牌负例、幂等与旧版本保留。修改运行环境的发布另外验证worker实际为true和现有DeepSeek视觉/独立搜索配置；内容发布本身不应修改这些配置。

## 后续实现顺序与验收

先做持久批次/队列与完成门禁，再接入现有官方/资料站/认证采集能力；随后做来源/媒体审核页、发布差异与真实云端验收页。pgvector与自动适配更多站点独立评估，不阻塞正确入账。

必须包含的回归：少1个产品；同域重复计路线；无结果没有真实捕获；403被写成成功；未核图已封版；两面不同版本误配；单年与跨年串线；第三方覆盖官方；候选内容变更后沿用旧审核；向量缺模态/旧输入；云端基线漂移；重复发布；任务中断恢复；私有图越权；hash损坏；发布成功但运行容器实际无文件。验收以真实云端结果为准，不以本机测试库或仅上传文件作为完成证据。
