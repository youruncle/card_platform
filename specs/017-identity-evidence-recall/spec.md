# Feature Specification: 识别字段证据与采购召回优化

Created: 2026-10-15
Status: Implementation authorized
Input: 用户确认按前述三项路线开始优化。保留所有既有未提交工作。

## User Scenarios & Testing

### US1：未知字段不会变成确定身份（P1）
识别没有可靠年份、卡号或主体时，用户仍可录入草稿并查找订单；系统必须保留未知状态和原始证据。
验收：位置词与传记年份被移除后仍有字段级问题记录；高置信度不把无证据结论升级为核实；入库兼容值不得成为采购匹配的真实年份。

### US2：多主体和未知主体也能发现订单（P1）
多人卡可按各主体分别查找；有正面图和具体产品的缺姓名卡可按产品检索，查询范围始终有界。
验收：三人卡的三次主查询分别覆盖三位；普通姓名别名行为不变；作品标题优先；泛称 Topps/NBA/未知产品不发起广泛搜索。发现订单不等于确认同款。

### US3：失败原因和回归结果可解释（P2）
返回订单但无法核实的场景明确标为未能匹配，只有完整空结果才标未找到订单。维护四张真实失败卡的去隐私证据集及正常/错误对照。

## Requirements
- FR-001 每个核心字段有 unknown/proposed/verified/conflicted 状态、来源、原文证据、问题码；置信度不是核实依据。
- FR-002 视觉模型提议与经过既有来源校验的目录依据必须区分；不增添外部模型调用。
- FR-003 新扫描的存储兼容值、关联定义和照片绑定必须留存；只有绑定仍有效才可在采购视图恢复未知字段，不能撤销后续人工校正，包含字段值恰好相同的明确身份确认。
- FR-004 主查询最多三次（原调用方上限保持），具体产品兜底最多一次；公开商品编号优先；召回不改变同款、付款、运费、占用和唯一性准入。
- FR-005 完整非空订单结果一律不能报告 not_found；未完成结果继续 incomplete。
- FR-006 回归集覆盖 862、873、875、876，以及错产品、少主体、位置词、日期与传记年份；不得记录账户、订单号、价格、私有路径或凭据。
- FR-007 本轮仅优化现有识别和采购通路，不批量重识别/更改历史账本，不新增全账户索引或更换模型。

## Key Entities
字段评估：字段当前值的证据状态与出处。存储绑定：识别结果与当时定义、限编/评级及两面图摘要的关系。订单检索结果：查询完整性、返回订单与同款确认分别处理。

## Success Criteria
- SC-001 固定四例的字段与召回预期及错误对照全部通过；分别报告字段正确、召回命中和错误自动写入，不以四例推算全库识别率。
- SC-002 未知发行年不再成为新扫描卡的采购年份证据，改图/改身份后旧评估不生效。
- SC-003 完整非空搜索结果为未匹配、空搜索为未找到；非空失败不改账本。
- SC-004 现有相关回归无新增失败；报告实际运行范围与剩余局限。

## Assumptions
现有存储身份要求年份非空，本轮保留兼容存储并对采购消费端做绑定后的真实值投影。历史卡无新绑定则保持当前语义，避免用旧识别撤销人工校正。手机确认采用用户明确提交身份，不据旧自动结果覆盖。
