# 图鉴管理首版设计

## 目的与已确认范围
知识管理以图鉴表格为主入口，右侧详情面板呈现精确版本及来源，提供字段纠错提案与审核。用户已确认表格＋详情面板、提案审核和开始实施；实现沿用 Next.js/TypeScript、FastAPI/Python、PostgreSQL、淡绿白色样式。串行实现，最后一次独立整体审核。仅本地，不部署、不 push/merge。

## 基线与依赖
隔离分支 codex/atlas-management-20261030 从原仓库 HEAD 64cf55d1 建立。原工作区大量未提交内容不纳入。只读依赖另一个工作树的三文件图鉴读取适配（清单见 readonly-dependency.json），复制到本工作树验证；没有写入该工作树或部署它。报告 atlas-browser-integration-20261029.md 与 atlas-readonly-release-readiness-20261029.md 已读。既有 /knowledge/manage 是词典/批次/发布/回滚长页，迁至 /knowledge/manage/legacy 并保留。

## 方案取舍
1. 复用知识审计日志保存提案及审核事件，已审纠错进入不可变发布快照的 atlas_corrections，再由派生目录应用。选此方案：已有 JSONB、UUID对象和幂等唯一键，无生产 schema 迁移；官方附件和来源本身不改写。
2. 新建 proposal/field 表：查询更直接，但首版增加迁移成本，暂不采用。
3. 直接改 card 实体：无法覆盖来源附件行且易绕过审核，不采用。

## 数据与安全
每次提案保存 published_version_id、目标 source-local card_id、身份及来源hash指纹、字段旧值/新值、理由、HTTP(S)证据、提交人/时间。字段限定为球员、卡号、子集、平行、总编、年份、签字；图片展示及相关问题可用证据提出，不提供上传。全局 canonical 不凭 source-local ID 冒认。未知值保留 null，流水分子/评级/品相不进入同款身份。
提案与审核都从登录用户取得身份并服务器检查 knowledge_member 角色；读权限不足以写入，不信任可伪造 X-Knowledge-Actor。提交/审核具有请求幂等键与内容绑定。共享 workspace/publish 锁序列化并发；旧发布版本或同目标已审草稿导致409。批准仅成草稿，显式现有发布后可见；自动官方来源发布只携带已发布覆盖，不带出人工纠错草稿。已批准但未发布的草稿可经再次审核驳回，解除回滚/自动水位变更后的过期阻塞；已发布历史不可修改。驳回不改发布态。发布/回滚保留原路径，收藏/账本/估值/实卡不改。
纠错覆盖保留原字段来源，增加字段级审核依据；源数据漂移则不应用旧覆盖并标记冲突。发布快照纳入覆盖及提案ID，因此回滚恢复对应纠错集。待审提案不阻止其他来源自动发布，但旧水位审核需重提。

## 界面
年份→品牌/制造商→产品→子集；球员/卡号精确搜索；每行是明确版本。身份确认、待确认、冲突及无图、单面、双面分别筛选。指标单列来源记录、来源内确认、待审身份与图片完整度；全市场分母未知。缺图不删行。详情有身份、正反图、字段来源、相关版本、提案审核记录；编辑→预览旧/新/影响→提交→批准/驳回。手机详情全宽。URL保留筛选/分页/选中项，关闭和浏览器返回可用。加载/空/失败/待审均明确，网络重试复用请求键，取消不写入。页面无演示数据。

## 非目标
合并/拆分、自动改收藏账本、实卡重写、估值、爬图、上传、生产迁移、部署与 push/merge。

## 验收
用隔离 PostgreSQL 实测提交/幂等/角色/并发/审批/发布/回滚；定向 Python 与网页回归、typecheck、可用 lint/构建检查；真实浏览器桌面/手机流程截图；真实冻结快照只读渲染验收与测试夹具严格区分。
