## Important

1. **Rollback can strand an approved draft and block all future publication.** `apps/api/src/card_platform/knowledge_atlas_corrections.py:263` rejects any approved/unapplied proposal whose base differs from the published version. Trigger: publish v2, approve a proposal against v2, then roll back to v1 before publishing that proposal. Subsequent manual or automated publication returns 409. Recovery is also blocked: `review()` rejects changing an already-approved proposal at line 201, while its competing-draft query at line 209 prevents approving a replacement. Reproduced against the isolated PostgreSQL: publication, rejection and replacement approval each conflict. Add an auditable way to discard/reject/supersede an unpublished approved draft, and derive current state from the latest event consistently in list, competition and publication queries.

2. **Automatic source-only publication consumes atlas drafts without explicit atlas publication.** `apps/api/src/card_platform/knowledge_repository.py:444` calls `snapshot_corrections()` unconditionally; `knowledge_atlas_corrections.py:255` adds every approved/unapplied draft. Existing automatic ingestion invokes this method with `official_source_keys` (`scripts/sync_official_checklists.py:248`, also history sync). Trigger: approve a correction, then an unrelated official source is automatically refreshed. Its source-only publication includes and marks the atlas correction applied, contradicting the UI/spec promise that approval remains a draft until explicit publication. Reproduced an unrelated scoped publication changing total 10 to 25. Carry already-published overlays during automatic publication, but do not consume new drafts. Account for the resulting version advance in the draft recovery/re-review lifecycle.

3. **The fingerprint does not bind the immutable source evidence.** `apps/api/src/card_platform/knowledge_atlas_corrections.py:34` hashes visible identity plus normalized source links, omitting `source_key`, `source_checksum`, `source_variant_label` and `official_artifact_sha256`. Trigger: an official attachment is replaced with new source bytes/checksum while displayed identity and URL/locator stay the same. A previously reviewed overlay still passes line 277 and is applied to that new source without a conflict. Reproduced changing both source checksum and attachment hash while preserving displayed identity: old total override applies and no `correction_conflict` appears. Bind the proposal to relevant source identity/evidence hashes as well as displayed values, with coverage for both changed-source rejection and unchanged-source carry-forward.

4. **Conflicting image evidence is presented as a reviewed pair and its provenance is hidden.** `apps/api/src/card_platform/knowledge_browser.py:866` validates pair hashes/record equality but does not downgrade a pair whose source mappings require review. `apps/web/components/knowledge-atlas-manager.tsx:81` consequently renders `已有来源审核配对`; the detail never renders returned `source_mappings` or image provenance, only the backbone source links at line 82. Trigger: both images from one record assert total 99 for a target card with total 25. Reproduced `mapping_status=needs_review`, `serial_total_conflict`, and simultaneously `image_status=paired`. The manager still presents a positive pair label without the conflict or external-record source. Separate same-record face pairing from reviewed target association, expose external source/provenance/conflict details, and withhold the positive review claim when mappings conflict.

## Minor

- **Published and unpublished approvals are indistinguishable.** `knowledge_atlas_corrections.py:97` ignores `atlas_applied`; `apps/web/lib/knowledge-atlas.ts:14` labels every approval `已批准 · 等待发布或已发布`. This prevents operators from checking which approved proposal still needs publication, or which published correction was rolled back. Expose application version/current lifecycle state alongside immutable review history.
- **Correction metadata can contradict corrected values.** `knowledge_atlas_corrections.py:303` updates only identity status and pairing; `atlas.serial_status` and `autograph_status` remain derived from original source fields. Clearing a known total can therefore leave `serial_status=known`. Either recompute effective metadata or explicitly distinguish original-source assertions from reviewed effective values.
