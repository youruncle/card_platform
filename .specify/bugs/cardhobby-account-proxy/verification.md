# 卡淘账号检查受失效全局代理阻断

日期：2026-09-26

## 症状与根因
获取成本返回 NETWORK_ERROR，阶段 session_check，连续两次 ConnectError，每次约5秒。账号客户端原先默认读取 HTTPX 环境代理；launchd API 配置 HTTPS_PROXY=http://127.0.0.1:7897，本次该端口没有监听服务，实测经代理连接失败。客户端无法检查 Cookie，自然无法进入既有的凭据自动登录逻辑。历史日志未保留底层连接详情，不能断言历史每次错误均来自同一个代理故障。

## 修复
仅卡淘账号客户端设置 trust_env=False，直连卡淘。其他海外数据源的代理设置保持原样。保留网络错误与认证失效的区分、GET 有界重试和登录 POST 不重放规则。

## 验证
- 新增环境代理故障回归：修复前重现相同 NETWORK_ERROR；修复后检查正确识别未登录。
- 账号单测及临时独立 PostgreSQL 集成测试：31 passed；覆盖保存加密凭据、过期 Cookie 自动登录、短信挑战及账户隔离。
- 使用真实网站、无 Cookie 且设置失效环境代理：成功识别未登录。
- 真实原账户：凭据已保存，旧 Cookie 无效；使用保存凭据登录成功，随后登录检查为 True，新会话已保存。未输出密码/Cookie，未修改成本。
- 发现重启后的原项目 .runtime/postgres 未运行，按其 postmaster.opts 恢复 5432 服务；排查时短暂启动的 Homebrew 默认数据库已停止，未向其中导入或修改业务数据。
- 重启 com.cardplatform.api 加载修复，/health=ok，/health/ready=ready。
