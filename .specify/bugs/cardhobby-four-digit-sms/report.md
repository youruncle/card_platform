# 卡淘四位短信验证码被本地校验拦截

- 样本：用户 2026-10-04 截图，四位数字输入后显示浏览器格式不符提示。
- 根因：表单 pattern 和 API 长度校验均固定为六位；请求尚未到卡淘即被拒绝。
- 修复：前后端统一允许 4–6 位 ASCII 数字，保留必填、最大长度及数字校验，保留前导零。验证码真实性仍由卡淘验证。
- 复现：修复前四位和前导零四位用例在前端原生表单校验、后端接口校验均失败，六位对照通过。
- 验证：前端账号与购入成本相关测试 64 项通过；后端账号及验证码测试 35 项通过；Next.js 生产构建、类型检查通过。
- 限制：使用组件 DOM 和接口测试验证本地提交路径，没有使用真实短信执行卡淘登录，也未运行全仓库测试。
