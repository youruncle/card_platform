# 扫描后预览加载与处理等待

日期：2026-10-31。用户确认两种现象都有：扫描停止后仍等待裁剪识别；卡片数量已出现但图片加载慢。

## 复现与根因证据

- `FlatbedBatchPanel` 的整版缩略图、单卡缩略图、配对图原先全部请求原始图片。最近四个本地真实整版记录为 6.37、6.63、6.63、9.25 MiB，单卡约 249–448 KiB；其中两个记录共享同一原图，共三张不同整版原图。
- 嵌套定义的 `SheetPreview` React 组件在父组件状态更新时更换组件类型、卸载重建；打开大图、处理状态变化会重新创建已经加载的图片节点。
- 云端当前真实八卡整版检测实测 2.01 秒。独立 OCR 单卡剖析一次耗时 10.07 秒，文字检测两轮累计 6.12 秒；CPU 占用和运行环境影响绝对耗时。
- Linux OCR 先用原尺寸卡片检测文字来判断方向，再以原图旋转后的 1536px 图片提取正式文字。判断方向不需要第一轮原图尺寸。
- 本机扫描文件虽已到浏览器，原 UI 必须等上传、裁剪、方向与文字分析全部返回后才显示任何图像。

## 修复要求与方案

1. 整版预览最长边 960px，单卡缩略图最长边 320px；点击放大仍请求原图，存储和识别用原图保留。
2. 复用已有私有派生图缓存、配额和源内容哈希。所有缓存读取及 304 前先检查当前账户所有权；旋转内容变化后重建小图；原图丢失不提供缓存副本。
3. 源文件的 `variant=original` 为兼容默认值。不存在或拒绝裁切的区域继续标记参考图，不提升为可导入裁图。
4. 用稳定的普通渲染函数输出整版区域，保留已经加载的图片节点。
5. 本机取图完成后通过 Blob URL 立即显示整版，等待云端处理期间和上传失败后均保留；替换和卸载时撤销 URL。
6. 仅方向判断文字检测限制最长边 960px、不放大小图；正式 OCR 仍从原尺寸像素旋转后以 1536px 提取。方向与真实文字输出须与原逻辑回放对比。
