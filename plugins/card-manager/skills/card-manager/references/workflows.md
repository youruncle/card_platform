# 成交研究、恢复与确认

## 本次真实研究

`get_card_detail` 中的估值有原研究日期；读到历史值不是本次检索。新研究绑定当前正背原图SHA256和身份，照片或身份有变化须重建研究。

`start_card_research` 返回任务编号。服务端实际尝试eBay已售检索与卡淘历史接口，保存查询、执行时间、响应捕获和失败诊断。进入 `review_required` 后，用户在返回的研究链接核对本卡、来源原文及候选实卡图。不能将搜索计划、旧缓存、响应空壳、403、超时改称“已查无成交”。两市场都尝试过也不意味着两市场都有支持价格。

平台研究页可补商品链接、实卡图链接和逐项核对字段，服务器重新保存原文与图片。每条需核球员、品牌、产品、赛季、子集、完整卡号、平行颜色与纹理、总编、评级、品相/瑕疵、实际成交日与金额、原币、运费、卖家及重复实卡。挂牌、整包、撤架、Best Offer实际金额未知、不同版本或评级、不可核图聚合不进入同款成交。本件历史单列；流水/卡面/寄售或再上风险不重复计数。

当前合同至少三条近期独立卖家同款公开成交才给观察区间。单来源支持必须显示另一来源的本次尝试和限制。外币需有日期和来源的汇率；运费另列。结构validate通过仅代表合同门槛，不证明人工描述真实；用户必须查看当前捕获。公开落槌不代表已付款。未审核、必要信息缺失或证据不足均保留null，不用采购成本、旧系统价或经验补价。

审核通过后读取 `get_research_result`，展示来源、日期、接受/排除原因和参考区间，再准备发布。`prepare_research_publication` 只收run_id、当前revision及幂等编号；发布仍需平台操作确认。保留旧估值历史。

## 照片与恢复

`prepare_card_import` 只创建识别草稿。对三附件或多卡图先恢复逐项任务状态，别把文件数量当卡片数量，别猜正背对应。review_required需要核图/校正，不重跑识别代替确认。

断线后先 `list_jobs`，再按编号查询原任务。重试仅指定失败且可恢复的项，保留原重试请求编号应对超时。已保存交易/入库操作重复执行回读原结果，不生成新的逻辑请求。不同内容复用幂等编号会冲突，需要用户确认这是否确为新请求。

## 权限恢复

AUTH_REQUIRED：在ChatGPT重新连接并通过原平台登录授权，不在聊天传密码或token。
FORBIDDEN：展示缺少的授权能力或连接设置，不换账户/猜owner。
NOT_FOUND：重新查本人编号，不用他人UUID探测。
SOURCE_BLOCKED：显示本次真实诊断和可行恢复步骤，不能转成空成功。
REVISION_CONFLICT：重新核对最新卡片/证据，重新准备和批准。
RETRY_EXHAUSTED：保留成功结果，检查照片或来源，必要时建立明确的新任务；不循环换幂等编号。
