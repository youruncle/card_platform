# 我的卡库 · iPhone 客户端

第一阶段：Capacitor 8 + React，复用现有 FastAPI。页面资源打入安装包；服务端地址必须为 HTTPS。保留桌面网页和高拍仪流程。

## 开发与验证

需要 Node 22+。在本目录执行：

```sh
npm ci
npm test
npm run build
npm run ios:sync
```

网页开发仅允许回环 HTTP。默认 Vite 在 `127.0.0.1:5178`，代理 API 到 `127.0.0.1:8000`：

```sh
VITE_MOBILE_DEV_ORIGIN=http://127.0.0.1:5178 MOBILE_DEV_API=http://127.0.0.1:8000 npm run dev
```

仓库根目录的隔离验证命令（PostgreSQL 16、API `.venv` 已安装）：

```sh
scripts/test-mobile.sh
MOBILE_BROWSER_CHECK=1 scripts/test-mobile.sh
```

这些脚本新建并删除临时 PostgreSQL 和图片目录，不读取本地 `.env`、不导入现有收藏。浏览器测试使用本机 Chrome、生成的图片和明确标注的外部模型边界样本；不代表真实识别准确率或 iPhone 真机测试。

## 连接现有腾讯云

当前手机版固定连接 `https://cardsp.cn`，登录只需用户名（邮箱）和密码，不显示服务地址输入。生产/原生版本忽略旧 `VITE_API_ORIGIN`。旧地址会话清除后重新登录，原域名会话保留。锁定时按账户显示倒计时，支持密码显隐和网络错误提示。仅浏览器DEV允许 `VITE_MOBILE_DEV_ORIGIN` 指定回环地址；不要将 API 密钥写入Vite环境变量。

开发调试可以用现有 SSH 权限将云端 `127.0.0.1:3000` 转发到本机回环端口，然后将 `MOBILE_DEV_API` 指向该端口；这只用于开发机，不是给 iPhone 的公网地址。不提供任意公网 HTTP/ATS 豁免。

服务端模型密钥尚未配置时，任务会明确失败。实际识别和估值需要在服务器单独配置并验证，不复制本地 `.env`。

## iOS 工程

`ios/App/App.xcodeproj` 已生成，使用 Swift Package Manager。需要完整 Xcode 26+ 才能解析 iOS SDK、编译、签名和安装：

```sh
npm run ios:sync
npm run ios:open
```

在 Xcode 选择自己的开发团队、唯一 Bundle Identifier 和测试设备。当前测试标识为 `cn.cardsp.alpha.local`，沿用已有匹配的开发签名。2026-10-12 使用 `/Applications/Xcode.app`（Xcode 27）编译签名，并安装、启动 1.1.0（build 3）到已配对开发 iPhone。未修改系统默认 xcode-select；命令通过 `DEVELOPER_DIR` 指定完整 Xcode。开发描述文件在北京时间2026-10-16 09:28:29到期，届时需更新签名并重新安装。

`SceneDelegate` 必须使用 `CardBridgeViewController`，它注册原生 `SessionVaultPlugin`；凭证存在 Keychain，使用 WhenUnlockedThisDeviceOnly，不写 localStorage。浏览器预览只在内存保留凭证，刷新后需要重新登录。

原生请求通过显式 CapacitorHttp 调用，禁止重定向，照片按原生 multipart 结构编码。全局 fetch patch 关闭，以免忽略 AbortSignal 和重定向选项。iOS 原生请求无法真正取消已发出的上传：界面会丢弃取消后的响应，重试复用请求 UUID 防止重复任务。照片与原生 HTTP 的实际内存占用、Keychain 和相机行为仍需真机验证。

## 行为与边界

- 四个入口：卡库、录卡、任务、我的；任务列表显示最近 100 条待人工确认来源的录卡任务。
- 新服务器支持正面、背面或双面识别；单面提交需明确选择。旧服务器仍要求双面。草稿按服务地址和账户隔离。上传完成清除同一请求编号的草稿，不清除后来编辑的新草稿。
- 手机任务识别成功后等待人工确认；桌面任务保持原有自动入库。
- 确认时校验必填身份字段，未知赛季不自动填今年；保存照片与任务证据。
- 退出清除会话与当前草稿；设备会话可撤销。服务器验证账户所有权，图片没有公开读取权限。
- 本地 Mac 卡库、交易、图片、知识库均未迁移。真实照片请专门提供测试样本，首版邀请与 TestFlight 留到下一里程碑。
- 目前未实现离线卡库、上传断点续传、后台上传、推送或完整原始 HEIC 文件保留。相机/相册取出的图像在客户端转为 JPEG 后上传；服务端保留收到的图像及裁切、判向结果。照片处理前后的设备原文件追溯属于后续完善项。

## 第二阶段：单面、取景裁切、全库排序、缩略图

- `/v1/client-capabilities` 声明能力，仅404视为旧服务器。单面/补拍使用`/v1/capture/jobs`；原`/v1/mobile/jobs`和扫描仪双面协议保留。
- 裁切编辑保留标准化源JPEG，每次从源图重建四角透视及旋转。拍后确认卡面或评级盒范围；保留整张也冻结配方。离线可保存源草稿，联网再请求提议。
- iOS `CardCameraPlugin` 提供AVFoundation预览、限频Vision提示、手动快门，返回临时文件后由JS读取并调用release清理。权限/后台/取消关闭会话。没有插件时仍可使用系统相机；2026-10-12 已通过Xcode构建，但相机权限、拍摄及内存行为尚未做真机操作验收。
- 全库排序由后端在最终估值/持仓成本计算后执行；分页使用60秒、绑定账户的快照，刷新/排序/筛选变化重新建立快照。页面显示更新时间。
- 列表320px、详情960px、点开才读取原尺寸处理图；私有接口每次校验权限，503有限退避及手动重试，不自动退回批量下载原图。
- 补拍默认只更新原卡图片，版本冲突要求重新打开原卡；可选主身份差异仅在勾选后接受；已有审核或估值记录的卡片需使用网页身份审核修改，补拍只补照片。

发布顺序：备份 → 停止并排空旧识别worker → 执行`0079_capture_sides.sql` → 同时更新API/worker及共享源 → 新客户端验证。不能让旧worker继续领取单面任务。回退时先关闭新录卡入口、停掉新任务领取；保留增量数据库字段，不能把已有单面记录强改回双面。首版排序快照为单进程内存；多API进程部署前需改共享快照存储。

2026-10-12 已随0.6.0发布云端并安装iOS开发测试包；HTTPS连通及真实卡样本验收仍待完成。详见 `../../specs/015-player-price-index/deployment.md`。
