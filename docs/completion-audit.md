# 完整性审计

审计口径来自项目最初的四组需求。只有功能证据、全链路测试、前端生产构建和部署准备均达到对应验证口径后，项目才可标记完成。

## 1. 个人卡库

| 要求 | 状态 | 当前证据 |
|---|---|---|
| 球员、年份、品牌、卡种 | 已验证 | `card_definition` / `card_set`；录卡 API 与前端表单；PostgreSQL E2E |
| RC / Auto / Patch | 已验证 | 三个可组合布尔字段；schema 与领域测试 |
| 编号与限编 | 已验证 | `card_number`、serial number/total；数据库约束 |
| 买入价格 | 已验证 | 原币、费用、汇率和交易流水；E2E |
| 当前估值 | 已验证 | 估值快照、最新估值视图、前端管理 |
| 已实现/未实现盈亏 | 已验证 | 移动加权成本、超卖保护、组合汇总；单元与 E2E |
| 交易与估值历史 | 已验证 | 详情 API 与前端历史面板 |
| 初始五张收藏 | 待用户数据 | CSV 模板已准备；币种、部分赛季和卡号不能猜测 |

## 验证命令

```bash
.venv/bin/ruff check apps/api scripts
.venv/bin/pytest -q apps/api/tests --ignore=apps/api/tests/test_e2e_postgres.py
./scripts/test-e2e.sh
cd apps/web && npm run typecheck && npm run build
```

初始五张收藏仍需用户确认模板中刻意留空的币种、赛季/卡号等事实字段后导入；系统不会替用户猜测资产事实。
